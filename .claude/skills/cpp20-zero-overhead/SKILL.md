# C++20 零运行时开销条约（通用）

**只管运行期成本。** 命名、格式、异常策略、测试宏不在这里——那些另有执法处，本条约不复述，以免同一事实写两遍。

**「零开销」的定义**（C++ Core Guidelines 的 zero-overhead principle）：不为你没用到的东西付费；用了恰当的抽象，就要拿到与手写低层等价物一样的性能。它**不是**「尽量快」——快慢是测出来的，不付费是设计时决定的。

**与 CGL 的分工**：CGL 写实的条目，这里只引编号加一句结论，不抄论证。CGL 的 `Per.12`（消除冗余别名）、`Per.13`（消除冗余间接）、`Per.14`（最小化分配次数）、`Per.15`（临界路径不分配）**四条只有标题、正文是 `???`**（2026-08-06 的 `33bcd01` 仍如此）——这四条由本条约写实，也正是它存在的理由。

## 怎么用

1. 判断改动落在哪几组 → 读对应 reference 文件（下表「触发」列）。
2. 组内逐条对照：默认做法照做；要付开销的，走「例外登记」。
3. 任何「这样更快/更省」的主张，先过「验证阶梯」。

**完成判据**：新增或改动的代码里，每一个付费点要么在例外登记表有一行，要么经确认无付费——两者必居其一，不许悬空。

## 第 0 组 元规则

- **0.1 三笔账分开记。** 运行期指令与访存、编译期时间、二进制体积与模板膨胀，是三笔不同的账。把计算从运行期搬到编译期是**换账**，不是白拿；只有那笔计算本来就不该在运行期发生，才算赚。
- **0.2 未测量不声称**（CGL Per.6）。没有第 8 组阶梯上的一个数字，就不写「更快」「更省」「零开销」——注释里也不写。
- **0.3 先定位再动手**（Per.2 / Per.3）。不在热路径上的成本不进入本条约的讨论，按可读性定夺。热路径要有可测定义，见 4.2。
- **0.4 信任优化器**（Per.4 / Per.5）。别手写去替编译器做它能做的事，除非你能在反汇编里指出它没做、并指出改完之后做了。复杂代码不一定比简单代码快，低层代码不一定比高层代码快。
- **0.5 设计到可优化**（Per.7）。少可变状态、少别名、少间接、可观察行为窄——优化能力是设计出来的，不是 flag 拧出来的。

## 第 8 组 例外登记制

允许付费，但付得**有据**。一行登记五列：

| 位置 | 付了什么 | 为什么值 | 测量点 + 最近数字（日期） | 复核触发 |
|---|---|---|---|---|

- **位置**：`文件:符号`。用行号会漂。
- **付了什么**：具体账单——「每次注册一次堆分配」，不是「有性能开销」。
- **为什么值**：换来了什么。可维护性、ABI 稳定、卸载时能全部回收，都是合法理由。
- **测量点**：第 8 组四级里的哪一级、哪个用例，附最近一次的数字与日期。
- **复核触发**：什么条件下这笔账要重算——换 STL 版本、上移动端、该函数进了热路径。

登记表跟着代码走（同一文件的注释块，或就近一份 `OVERHEAD-EXCEPTIONS.md`）。规矩三条：无登记的付费按违规处理；一行不许写「先这样，以后再测」；一行登记只在它的复核触发条件成立时到期。

## 第 8 组 验证阶梯

四级各自能证明什么。**跳级即无效。**

1. **反汇编**（godbolt / `objdump -d` / `dumpbin /disasm`）—— 证明指令层面的主张：多出来的调用、内存屏障是否消失、是否真被内联。这一级免费且最常被跳过。它**不能**证明端到端更快。
2. **计数** —— 证明「零次」类主张：分配次数、虚调用次数、原子 RMW 次数。用 RAII 计数器，或替换 `operator new` 计数——**后者有链接坑，见文末**。这一级能把成本主张落成单测断言，是本条约里最接近硬门禁的手段。
3. **硬件计数器**（`perf stat` / ETW）—— 证明缓存与分支层面的变化：`cache-miss`、`branch-misses`、instructions。它回答「为什么」，本身不构成快慢结论。
4. **微基准** —— 到这才谈端到端。必须防死代码消除（`DoNotOptimize`）、取分布而非单次、并留意 `-O` / LTO / PGO 会让第 1 级的结论失效。

跳过第 1 级直接跑微基准，等于在噪声上做决策。

## 执法点小抄

本条约的「执法」一栏只引通用工具，取值域如下（名称按 clang-tidy / clang 23.x 实测有效）：

| 手段 | 能查什么 | 强度 |
|---|---|---|
| `static_assert` + 类型特征 | 尺寸、对齐、平凡性、`noexcept`、无 vtable、`is_always_lock_free` | 编译期失败，最硬 |
| 编译器警告（`-Wpessimizing-move` 等） | 反模式写法 | 可升 `-Werror` |
| clang-tidy `performance-*` | 拷贝、值传参、隐式转换、低效算法、枚举尺寸 | 提示，除非进 `WarningsAsErrors` |
| clang-tidy `clang-analyzer-optin.performance.*` | 结构体 padding、GC 反模式 | 提示 |
| 计数单测（阶梯 2） | 热路径零分配 | 可自动化，但要处理 `operator new` 替换的链接边界（见下） |
| 反汇编（阶梯 1） | 内联、屏障、向量化是否发生 | 需人读，结论须附在登记表 |

## 阶梯 2 的落地坑：替换 `operator new` 不总是接得住

计数分配最直接的想法是替换全局 `operator new` / `operator delete`。它在**动态库分家的构建里会静默漏计**，而漏计的计数读起来像「零分配」——假绿，比没有数字更坏。两处机理：

- **MSVC STL 的 `operator new` 是编译器生成的转发函数。** 替换实现必须链进**被计数的那同一个镜像**，否则该镜像内的分配走的仍是自己那份。缺了配套导入库（MSVC STL 的 `VaseCRT.lib` 一类）时，链接期会直接报出与替换函数相关的符号——这是好事；更坏的情形是链接通过、计数为 0。
- **启动期与跨 DLL 的分配可能被 CRT 抢先占位**（首块预留一类机制），计数器装上去之前就已经有过分配。

三条对策：

1. 优先用**显式 RAII 计数器**（自己代码里可见的计数点），把 `operator new` 替换当兜底而非唯一手段。
2. 计数**基线**要在装配完成后当场测一次再开始断言，别假设起点是 0。
3. 登记表的「测量点」列必须写明这个计数器**覆盖哪个镜像**——不写就是没写。
