# 组 1 分发形态 · 组 2 编译期

`cpp20-zero-overhead` 的第 1、2 组细则。元规则与例外登记见 `../SKILL.md`。

## 组 1 分发形态

每条都回答同一个问题：**这次分发，钱在运行期付还是编译期付，付几次。**

### 1.1 默认编译期分发
类型集合在编译期已知时，用重载 / `if constexpr` / tag dispatch / 策略模板，别上虚表。运行期多态留给「类型集合开放」这一件真正需要它的事。
- **执法**：对本不该多态的类型钉 `static_assert(!std::is_polymorphic_v<T>)`——一旦有人加虚函数，编译期响。
- **依据**：CGL T.5（泛型与 OO 各自强项，别混着用其短板）、T.82、C.132（别无理由 `virtual`）。
- **例外**：插件、扩展点这类开放集合——登记，理由通常写「类型集在编译期不可知」。

### 1.2 虚调用摊在批量上
一次虚调用的账单：取 vtable 指针 + 一次间接跳转 + **阻断内联**（去虚拟化要靠 profile 或 LTO 才发生）。所以把虚边界做**粗**：一次虚调用处理一批工作，别在逐元素循环里虚调用。
- **执法**：阶梯 1 看 `call` 是否还在、循环体是否被内联展开；阶梯 3 看 `branch-misses`。
- **依据**：CGL C.132。
- **反模式**：为了「将来可能扩展」预留虚接口——那是为没用到的东西付费（违反 0.1 与 zero-overhead 定义本身）。

### 1.3 类型擦除的默认账单
`std::function` / `std::any` / 自研 erased handle：默认**一次堆分配 + 双重间接**（擦除对象一次跳，管理表一次跳）。小对象优化（SBO）阈值随实现而变，**依赖它就是把自己的代码绑到某个 STL 版本上**。
- **执法**：`static_assert(sizeof(Fn) == kExpectedInlineBytes)` 把 SBO 假设钉死；阶梯 2 数分配次数。
- **例外**：需要跨编译单元存放可调用物时值得——登记，并注明当前依赖的实现与其阈值。

### 1.4 编译期多态换的是账，不是免费
CRTP、tag dispatch、`if constexpr`：运行期零成本，但**每种实例化都是一份独立代码**——编译时间与目标文件体积在涨。泛型接口被 20 种类型实例化，就是 20 份机器码。
- **做法**：类型无关的部分下沉进非模板核心，只在真正需要泛化的参数上泛化。
- **执法**：编译时间计时；符号计数（`nm` / `dumpbin /symbols`）。
- **依据**：CGL T.120（真要才用模板元编程）、T.84。

### 1.5 跨 ABI 边界的付费是设计的一部分
动态库边界上：模板**不跨边界**（要么显式实例化并导出，要么根本不导出）；边界上的多态用**函数表 / 描述符**，不用跨模块虚表（vtable 布局、new/delete 配对、STL ABI 都成了跨模块假设）。
- **依据**：CGL T.84（非模板核心实现提供 ABI 稳定接口）。
- **例外登记必写**：这笔钱换来的是独立构建与热装卸。它是**有意付费**，不是待优化的疏漏。

### 1.6 层次结构的两笔隐性账
- **虚基类**：每次成员访问多一跳（经 vbase 偏移取地址）。除非菱形继承真的无解，别用。依据 CGL C.137。
- **多态类的值语义**：有虚函数就抑制公开拷贝/移动，否则切片是静默的。依据 CGL C.67；执法 `cppcoreguidelines-slicing`。基类析构要么 public virtual 要么 protected non-virtual（C.35 / C.127）。
- **执法**：`cppcoreguidelines-virtual-class-destructor`、`modernize-use-override`（漏 `override` 会静默变成新函数而非覆盖，是一笔功能账不是成本账，但同一处检查）。

## 组 2 把计算搬去编译期

### 2.1 `constexpr` 是交出选择权，不是优化开关
标 `constexpr` 同时保留编译期与运行期两个版本，**且不保证内联**。所以「标了 constexpr」本身不构成性能主张；只有当有调用点真的在编译期求值，那笔计算才算省下来。
- **依据**：CGL F.4（可能要编译期求值就标）。
- **执法**：阶梯 1——看该调用点是否消失了。没消失就是还在付。

### 2.2 必须编译期就用 `consteval`
「只允许编译期求值」的语义用 `consteval`，运行期路径直接编译失败。这比事后断言硬，也比注释可靠。

### 2.3 不变式进 `static_assert`
尺寸、对齐、平凡可拷贝、移动 `noexcept`、无 vtable、`is_always_lock_free`——凡是「违反了就会在运行期付暗账」的性质，都写成编译期断言。运行期零成本，违反即编译失败。
- **依据**：CGL T.150（用 `static_assert` 校验概念匹配）。
- **执法**：本身就是执法手段。`misc-static-assert` 提醒 `assert` 该写成 `static_assert` 的情形。

### 2.4 常量表别把账留到启动期
`constexpr` 只保证能编译期求值；**有用户析构或非平凡成员的静态对象**仍可能留下动态初始化与退出期注册。跨边界/热装卸场景里，这既是一笔启动账，也是一笔卸载期风险账。
- **做法**：边界上的常量表用平凡类型 + `constexpr`（POD、无用户析构），让它落进 `.rodata`。
- **执法**：`cert-err58-cpp`（静态初始化可能抛）；阶梯 1 看启动路径里还有没有构造调用。

### 2.5 编译期成本的天花板
模板递归深度与实例化数量直接进编译时间；`concept` 检查失败信息也会随之膨胀。先量编译时间，再决定要不要为一个运行期收益引入更重的泛型 machinery。
- **执法**：编译时间计时（同一提交前后各一次）；`-ftime-trace` / `/d1reportTime`。
