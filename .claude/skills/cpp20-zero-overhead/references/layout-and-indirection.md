# 组 5 布局即速度 · 组 6 别名与间接层

`cpp20-zero-overhead` 的第 5、6 组细则。元规则与例外登记见 `../SKILL.md`。

## 组 5 布局即速度

性能通常由访存决定——`「Performance is typically dominated by memory access times」` 是 CGL `Per.16` 与 `Per.18` 的 Reason 原话。这一组的账都**不在指令数上，而在数据摆在哪**。

### 5.1 紧凑（Per.16）
成员按尺寸降序排，把 padding 挤掉；布尔标志打包进一个整数字段。`enum` 的底层类型能窄就窄（承接 4.4）。
- **执法**：`clang-analyzer-optin.performance.Padding`（报结构体 padding 浪费）、`performance-enum-size`；把关键类型的尺寸钉进 `static_assert(sizeof(T) == kWords * 8)`。

### 5.2 最常用的成员先声明（Per.17）
首成员偏移为 0 → 基址+0 寻址，省掉位移。次常用的往前排。
- **执法**：阶梯 1 看寻址形式是否带大位移；这是字节级的账，别为它牺牲 5.1 与 5.5。

### 5.3 线性访问（Per.19）
缓存算法偏好对相邻数据的线性访问。遍历模式决定 AoS 还是 SoA：**只读少数几个字段时 SoA 赢，整条记录一起用时 AoS 赢**——按实际访问模式选，不选流派。
- **做法**：让内层循环连续、无数据相关分支、迭代次数已知，向量化才有发生的可能。
- **执法**：阶梯 1 看有没有出现 SIMD 指令（`movaps` / `ldp`+`fmla` 一族）与优化报告的 miss 原因；`portability-simd-intrinsics` 提醒手写内在函数换来的是可移植性代价。

### 5.4 空间就是时间（Per.18）
更少的字节 → 更少的缓存行 → 更低的延迟。用 32 位句柄代替 64 位指针、用索引代替指针链，通常赚。
- **代价要如实登记**：句柄化把一次解引用换成一次表查找，且带来回收期的整理成本（见 6.2）。

### 5.5 并发写隔离到缓存行
不同线程写同一缓存行的不同字段＝false sharing：每次写都让对方那行失效。把并发写的字段各自对齐到一行。
- **执法**：阶梯 3 的 `cache-misses` 差异；`alignas(std::hardware_destructive_interference_size)`。
- **注意**：该常量各实现取值不一（64 / 128），它本身也进布局——用 `static_assert` 钉住期望值，别让它随风变。这条与 5.1 方向相反（紧凑 vs 摊开），冲突时按「谁跨线程」定优先级。

## 组 6 别名与间接层

CGL 的 `Per.12` / `Per.13` 只有标题、正文是 `???`。下面两节是本条约给的内容，采用时按「已写实」看，别去 CGL 找论证。

### 6.1 消除冗余别名（Per.12，写实）
同一对象能从两条路径到达时，编译器**无法证明它们不重叠**，于是：循环里每次迭代都得重新 load，store 之后也不能把值留在寄存器里，向量化直接放弃。
- **做法**：进热循环前，把循环不变的量读进**局部标量**；输出缓冲与输入缓冲不重叠（ separate 对象，或先算好再写）；用 `std::span` 明确边界，让长度在循环外就算完。
- **C++ 没有标准 `restrict`**：`__restrict` 是编译器扩展，不可移植且优化器未必采信——用上面这些标准写法达到同一效果。
- **执法**：阶梯 1，看那几次 load 有没有被提出循环。

### 6.2 消除冗余间接（Per.13，写实）
`p->next->next->field` 的每一跳都是一次潜在未命中，而且**地址不可预测，预取帮不上**。容器存指针（`std::vector<T*>` / `vector<unique_ptr<T>>`）等于把每个元素的访存都变成两跳。
- **做法**：存值（`vector<T>`）；需要稳定身份和 O(1) 复活的，用 **索引 / 句柄 + arena**，把指针链换成一次数组下标。
- **代价**：句柄化要额外维护 slot 有效性，回收时需要 mark/compact 或代际计数（generation）。这笔账必须登记——它是 5.4 的另一面。
- **执法**：阶梯 1 看解引用层数；阶梯 3 看 `cache-misses`。

### 6.3 一次付清
1.2 的虚调用、1.5 的跨边界调用、6.2 的指针链，账单结构相同：**一次调用的固定成本高，摊在批量上就便宜**。把 N 次细粒度往返合成 1 次粗粒度调用，是本条约里最少争议的纯赚。
- **执法**：阶梯 2 数调用次数（不数分配）。
- **反例**：批量接口让生命周期变长（一批对象同时存活），内存账反而上升——那是换账（0.1），不是白拿。
